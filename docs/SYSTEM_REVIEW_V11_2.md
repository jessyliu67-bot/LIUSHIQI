# 大爆炸 V11.1 → V11.2 代码与流程复盘

依据：实际检查 V11.1 完整源码、V13 300套资源ZIP、内置数据库和实际表头。**本报告不等于公司/商标/支付/广告平台法律合规审查。**

| 风险 | 在现有文件中发现的情况 | V11.2处理 | 遗留限制 |
|---|---|---|---|
| P0资源版本覆盖 | V11.1启动时会按打包资源更新模板指向，且下一批资源没有专门的映射确认机制 | V13哈希漂移保护；新ZIP只预检、不自动激活 | 正式版本切换/回滚需等实际新包到来后开发 |
| P0模板重复追加 | 300套已存在时，`/api/templates/import` 还可继续创建新模板编号 | 对300套已有数据库直接禁止旧入口追加，提示使用预检 | 大于300套的正式扩容需单独设计 |
| P1源数据统计错误 | V13实际CSV字段名为 `SKU` / `Product image URL`，旧清单按 `Variant SKU` / `Image Src` 统计为0 | 更正清单统计器；新增同时支持两类字段表头的资源体检 | 跨平台商品导入转换尚未完成 |
| P1缺少升级前备份机制 | 旧版README只提醒手动复制data和.env | 新增 `backup_windows.bat`、SQLite一致性备份与校验 | 备份ZIP未加密，`.env`需要单独保护；还未提供一键恢复 |
| P1问题入口分散 | 资产/批量主体/交付/API测试分散，用户很难一眼判断“系统是不是准备好” | 新增运行准备中心和单独诊断按钮 | 审核任务仍未统一到可断点重试的持久化队列 |
| P1双平台兼容性误认 | 现有工作流只有Shopify资产，原有4段Liquid不等于完整主题 | 增加平台能力矩阵，并明确SHOPLINE未实现项 | SHOPLINE 需要实际Sline、CSV和页面发布适配 |
| P2过度声称审核通过 | 离线包完整、政策变量已填充 ≠ 真实经营数据、授权、线上可用和AppLovin批准 | 体检和页面明确标出检查边界 | 真正合规核验与授权文件必须建立证据流程 |
| P2保密与安全 | 单机管理员、SQLite、公司文件、本地API密钥；不能当公网多用户SaaS | 本版不开放网络，操作日志与只读诊断，未暴露密钥 | 后续如多人使用需 RBAC、加密密钥存储和权限审计 |

## V13实检统计（不是300家独立商品总量）

- 模板组合：300；源文件：3,600；结构缺陷：0；固定组合未被改动。
- 商品标题行累计：9,460；SKU行累计：36,300（含20组模板对15个品类的跨模板重复）；外部图片URL行累计：9,460，其中Amazon链接引用9,460。
- 300套源文件中检测到2,100份涉及替换变量的源政策/页脚模板。此为**尚待主体配置的原始模板状态**，不等于已经生成的交付包发生2,100个独立错误。
- 程序未联网核验图片URL，也未取得其使用许可；不能声明图片全部正常或已获授权。

## 建议以后工作流（优先级）

1. **资源版本门禁（下批次）**：接收新ZIP → 源文件扫描 → 生成旧/新映射报告 → 人工确认300套对应关系 → 数据备份 → 原子切换 → 复检。禁止按目录顺序重新匹配商品与装修。
2. **主体与域名输入**：一份ZIP导入多家主体，按公司展示文件来源和字段差异；只补缺字段，支持任意粘贴域名；正式交付仍要求正确真实电话和独立邮箱。
3. **政策生成与版本**：七份政策及页脚同时填充，对真实性/服务承诺缺乏依据的字段停在待核验；整包成功后保存交付版本。
4. **双平台适配**：同一业务数据，经各自适配器输出 Shopify / SHOPLINE 的商品、装修和政策，不混用各自代码，不宣称未经测试的功能可用。
5. **质量分层**：离线结构通过、内部风险分析通过、人工事实核验、授权在线实测、第三方官方审核分别存状态。
6. **部署任务队列（未来）**：紫鸟一店一环境，任务指定唯一目标、逐步校验后继续，失败保留证据并可以断点恢复；未经授权不进行自动发布。
